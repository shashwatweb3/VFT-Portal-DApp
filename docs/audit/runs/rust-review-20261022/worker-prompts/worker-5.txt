## Purpose
Mainnet-bound Vara/Gear Sails smart contracts (no_std wasm32, gstd =1.10.0, sails-rs =0.10.2, Rust 1.91.0, overflow-checks ON in release). `launchpad/app` is a pump.fun-style bonding-curve launchpad that custodies native VARA (escrow, creator/protocol fees, small-sell payouts), sells 800M of a 1B token supply on a constant-product curve with virtual reserves, and on sell-out runs an 11-step async "graduation" to RivrDEX (wrap VARA, create/use pair, align price, add liquidity, burn LP, revoke roles, settle). `vft/app` is the per-launch fungible token.

## Scope
Findings only inside contracts/launchpad, EXCLUDING launchpad/tests/, tests-wasm/ and target/. vendor/vara-amm and awesome-sails are context only.

## Entry points
Every public Sails service method on Launchpad (Launch, Buy, Sell, Graduate, Unwind, Reconcile, ClaimCreatorFees, ClaimPayout, admin setters, queries) and Vft. Callers are arbitrary accounts/programs choosing args, attached value AND the gas limit of their message. Gear semantics: state before an `.await` is committed even if the continuation later traps or runs out of gas; attached value is refunded only on a trap before the first await; `wait_up_to` timeouts do not cancel the outbound message; other messages interleave between awaits; sends with non-zero value below the existential deposit are rejected.

## Trust boundaries
Untrusted users/programs → Launchpad. Semi-trusted admin (config, fee recipient). Launchpad → its own spawned VFT (trusted code) and → RivrDEX factory/pair/wVARA (external; a pair can be created and seeded by an attacker before graduation). Off-chain keeper only calls permissionless methods.
